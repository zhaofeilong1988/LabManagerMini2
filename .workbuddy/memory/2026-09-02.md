## Bug 修复：登记页「提交」不跳转
- 根因：register.wxml 提交按钮 `disabled="{{!agreed}}"` 静默禁用——未勾选「同意声明」时按钮灰色不可点，点击无任何回应（非逻辑错误，van-button/field/checkbox 链路均正常）。

- ⚠️ 更正（重要经验）：Vant Weapp 的 van-button / van-cell / van-grid-item 内部通过 `$emit('click')`（即 `triggerEvent('click')`）触发**自定义事件 `click`**，不是原生 tap。必须用 `bind:click` 监听，`bindtap` 会无响应（官方 issue #1725 明确「button 提供的是 click 事件而非 tap」）。van-field/van-search/van-checkbox 用 `bind:change`（detail 为字符串/布尔）。只有原生 `<view>/<text>/<button>/<image>` 才用 `bindtap`。

## Bug 修复：van-button 在 glass-easel 下 click 事件不触发（最终方案）
- 现象：改为 bind:click 后「提交申请登记」等按钮**依然不跳转**。
- 真正根因：app.json 开启了 `"componentFramework": "glass-easel"`。van-button 内部把 tap 处理器写成**动态事件绑定**（`bindtap="{{ disabled || loading ? '' : 'onClick' }}"`），该写法在 glass-easel 下不生效 → onClick 不执行 → `$emit('click')` 永远不发 → 页面上的 bind:click / bindtap 均收不到。而 van-grid-item / van-cell 用的是静态 `bindtap="onClick"`，所以它们正常（印证了为何 home 页正常、onboarding 页失灵）。
- 修复：把关键 CTA 的 van-button 全部换成**原生 `<button>` + bindtap**（与 exam 页按钮同模式，100% 可靠）：
  - pages/onboarding/index/index.wxml：goNextStep / goHome → `<button class="btn-main" bindtap="...">`
  - pages/onboarding/register/register.wxml：submitRegister → `<button class="btn-main" bindtap="submitRegister">提交申请登记</button>`
  - pages/onboarding/upload/upload.wxml：takePhoto/chooseFromAlbum → `.btn-upload-sm`；submitUpload → `.btn-main`；saveDraft → `.btn-sec`
  - components/training/training.wxml：enrollTraining/cancelEnroll → 原生 `<button class="btn-enroll">`（保留 catchtap 防止冒泡触发卡片详情）
- 样式：onboarding.wxss 新增 `.btn-upload-sm`；training.wxss 的 `.btn-enroll` 补全真实按钮样式 + `.btn-enroll--plain`。
- 移除：index/register/upload/training 的 json 中不再需要的 `"van-button"` 注册。
- 诊断：index.js / register.js 的 wx.navigateTo 增加 `fail` 回调，跳转失败会 toast 提示。
- ⚠️ 经验：**glass-easel 下尽量用原生 button 承载点击跳转；若必须用 Vant 交互组件，确认其内部事件绑定是静态的**。

  - van-checkbox → 原生 `<view class="declare-check" bindtap="toggleAgree">` 自绘 `.checkbox`（勾选直接翻转 `agreed`，不依赖任何组件事件）。

- ⚠️ 经验：**表单数据同步尽量用原生 input/textarea/view(bindinput/bindtap) 承载，不要依赖 Vant 表单组件的自定义 change 事件**。
